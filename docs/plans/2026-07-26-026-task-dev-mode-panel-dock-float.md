# Dev Mode 面板：固定 / 浮动可切换

**裁决（用户 2026-07-26）**：面板要能在**固定**与**浮动**之间切换。
**固定模式占据空间**（就是 U0-2 已经做出来的挤压布局：舞台按剩余宽度重新 fit）；
浮动模式浮在舞台上方，不改变舞台尺寸。

这是计划 §8 三个开放问题里的第一个，当初 U0-2 按「先固定挤压，不挡」处理，现在收口。

## 0. 出卡前要重测的基线（**执行者不要跳过**）

本仓四张卡的经验：**每次重测基线都会改写卡**。动手前至少确认：

- 现在的面板挂载点与布局在哪（U4 之后 `StoryRuntimeDebugPanel` 与 `DevModeContent` 都动过，
  `DevModeContent` 还被上游 revert 过一轮）；
- 舞台的 fit 逻辑怎么响应容器宽度变化（U0-2 做挤压时改的那套）；
- 面板宽度当前是写死的还是可变的。

把实测写进报告，与本节不符的地方以实测为准。

## 1. 范围

- **两种模式 + 一个切换控件。** 控件放在面板自己的标题栏（`Story Runtime` 那一行），
  要有可访问名——本轮刚把「可见按钮必须有可访问名」清干净，别又开一个口子。
- **固定模式**：现状不变（挤压，舞台重新 fit）。
- **浮动模式**：面板浮在舞台上，舞台恢复整幅。浮动时至少要能**拖动位置**；
  是否可缩放尺寸交给执行者判断，但不许出现"浮动了却挡死舞台且挪不开"。
- **模式要记住**（跟着 Dev Mode 的会话状态走，与快照选择器同级别的持久化即可）。
- 浮动模式下面板仍然要是**不透明阅读面**（`.nl-editor-surface`），压在舞台上更需要它。

## 2. 明确不做

- 不做多面板停靠系统、不做面板分离成独立窗口。
- 不动面板内部四个 tab 的任何内容（U4/U5 刚验收过，回归必须保持绿）。
- 不改舞台自身的 fit 算法，只是让它在两种模式下拿到正确的可用宽度。

## 4. 判据（orchestrator 所有，已定稿）

断言脚本：`tools/ui-verify/scenarios/u026-dev-mode-panel-dock-float.js`。
**执行者不许改这个文件，不许写新的 assert / scenario，不许在报告里下"通过"判定。**

### 4.1 模式的可访问名契约（这是接口约定，不是建议）

脚本判定当前模式的唯一权威是**切换控件的可访问名**，它命名的是"点下去会发生什么"，
与既有的调试 FAB（`Open preview debug tools menu` / `Close preview debug tools menu`）同构：

| 当前模式 | 切换控件的可访问名（en） |
|---|---|
| 固定 | `Float panel` |
| 浮动 | `Dock panel` |

必须走 i18n（en / zh 两份 key 都要有），**en 文案必须逐字是上表这两串**——脚本按
`^Float panel$` / `^Dock panel$` 锚定匹配。

为什么不用布局来判定模式：D-1 / D-2 量的**就是**布局，再用布局反推"现在是哪个模式"，
这两条就变成自己证明自己。

### 4.2 两条实现约束（为可测性，也是本仓已知的坑）

- **拖动必须响应真实指针输入**（`pointerdown` / `mousemove` / `pointerup` 一族）。
  不要用 HTML5 `draggable`：本仓的 `draggable` 需要 `.nl-drag-source` opt-in 才生效，
  而合成 `DragEvent` 根本无法证明它能用（见 [[html5-drag-requires-opt-in]]）。
- **舞台的 fit 面积必须仍由 `StageViewportFrame` 自己量**（它现在用 ResizeObserver 量自己的盒子）。
  固定模式下面板是舞台的 flex 兄弟，浮动模式下必须脱离文档流，**不能**改成给 fit 传一个手算宽度。

### 4.3 「模式要记住」的边界

§1 写的是"与快照选择器同级别的持久化即可"，而快照选择器**没有任何跨窗口持久化**。
所以本卡要求的是**Dev Mode 窗口会话内**记住，具体两条：关闭再打开面板（D-6a）、
以及时间线跳转导致的整个 game session 重挂载（D-6b）。
**跨 Dev Mode 窗口重启的持久化不在本卡范围内**，不做也不算红。

### 4.4 断言清单（改前标定见 §4.5）

| id | 判据 |
|---|---|
| D-1 | 固定：`舞台 fit 面积宽 + 面板宽 == 窗口宽`（±2px）——面板确实占位 |
| D-2 | 浮动：`舞台 fit 面积宽 == 窗口宽`（±2px），且面板仍可见（宽 > 0） |
| D-3a | 固定：舞台盒装得下自己的 fit 面积，且整体在窗口内 |
| D-3b | 浮动：同上 |
| D-3c | 两种模式下舞台盒的**宽高比完全一致**（±0.01）——证明是重新 fit，不是裁切也不是拉伸 |
| D-3d | 浮动把固定模式下被面板拿走的宽度还给了舞台（仅在固定态是宽度受限时判定，否则记 note 跳过） |
| D-4a | 浮动：拖面板标题栏，面板按拖动位移移动（±8px） |
| D-4b | 浮动：往窗口外猛拖之后，面板仍**完整**在窗口内（要夹住） |
| D-5a | 面板标题栏有模式切换控件，且有可访问名（按 §4.1 契约锚定） |
| D-5b | 切换控件双向可用（固定 → 浮动 → 固定） |
| D-5c | 面板内**没有**任何可见控件缺可访问名 |
| D-6a | 浮动模式在关闭面板再打开后保持 |
| D-6b | 浮动模式在时间线跳转（game session 重挂载）后保持 |
| D-7 | 浮动：面板**不遮住舞台中心**（`elementFromPoint(舞台中心)` 不落在面板里） |
| D-8 | 浮动：面板仍是不透明阅读面（`.nl-editor-surface` 背景 alpha == 1） |

抓拖动点用的是标题栏上**第一个不落在任何控件上**的位置（面板标题栏右侧有快照 `Select`，
盲抓中点会抓到那个下拉框，那不是在测拖动把手）。
