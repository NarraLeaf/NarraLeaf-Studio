## 背景

`Camera extends Displayable`，`story.camera` 是 story 级单例、姿态**跨场景保留**、随存档序列化（`Story` 构造时可传初始姿态）。引擎侧能力自 0.16.0 起就位（`camera.pan/zoom/rotate/darken/reset`，走与图片相同的 Transform 管线）。Studio 目前**零入口**——这是 §2 的 D6 缺口里表现力成本比最高的一项。

## 工作项

### WI-1 payload 与编译

按 §7.1 新增 `action: "camera"`：`operation: "pan" | "zoom" | "rotate" | "darken" | "reset"`，加上 `position?`（pan，复用既有 placement 机械）、`zoom?`、`rotation?`（度）、`darkness?`（0–1）、`durationMs?`、`easing?`。

- 编译落点 `nlrStory.camera.<op>(...)`；编译上下文已持有 `nlrStory`（`storyCompiler.ts` 的 `SceneCompileContext`），无需新解析机械。
- **数值入参一律钳制**（`darkness` 0–1；`zoom` 给一个合理下限避免 0/负值）。这是刚踩过的坑：引擎 `Darkness` 不自钳，作者输 `2` 会产出无效 CSS 而**静默失效**；`storyCompiler.ts` ~:2318 与 `storyStageSnapshot.ts` ~:557 的 `Math.min(1, Math.max(0, x))` 是本仓既有 idiom，照抄。
- schema：新增 action kind 是**加性**的，不 bump 版本（除非你发现必须 bump——那要停机报告）。

### WI-2 指令 spec

一个 token `/camera`，第一个位置参数是 operation 枚举：`/camera zoom 1.5 d=0.8`、`/camera pan left d=0.6`、`/camera darken 0.6`、`/camera reset d=0.6`。守 bible：B1 槽位顺序、B6 枚举规范值 + 别名（补全插入规范值）、B7 时长用秒且键为 `d=`（存储仍 ms）、B9 核心齐全才落行否则草稿行。别名可给 `/cam`。

`pan` 的位置参数**先用既有 `placementParam()`**（left/center/right），精确 `xalign/yalign` 走检查器——§11 开放项 2 授权你在真机试用后提案调整（若发现三档太粗，可提案行内接受数值，写进报告而不是直接扩大本卡范围）。

### WI-3 检查器

镜头动作的检查器区：operation 切换 + 对应参数 + 时长/缓动。复用既有转场/变换编辑区的控件惯例与布局，**不发明新 UI 语言**、无解释性文案。

两处**作用域告知**是 §7.1 明确要求的，但**必须用界面自身表达，不是写一段说明文字**（风格铁律优先）：作者需要能意识到 ①镜头姿态跨场景保留、②`/camera darken` 与 `/vignette` 不是一回事（前者是整个舞台的亮度 filter，后者是场景内的暗角遮罩层）。可行手段：字段命名、`/camera reset` 在补全里的显著位置、检查器区标题的措辞。做不到就在报告里说明并提案——不要为此塞一段 tooltip 教程。

### WI-4 演出透镜时长派生（§12.7 硬要求）

`deriveBlockTiming`（`storyStagingLens.ts`）要认识 `camera` 动作的 `durationMs`。否则"镜头推近 + 立绘移动同时进行"这个最典型用法放进 `/parallel` 时，镜头轨会渲染成未知时长的等宽虚条。补一条投影测试。

### WI-5 其他消费面对齐

新 action kind 会经过若干通用面，逐一确认不炸且表现合理：行摘要（`blockOverview`/`describeBlock`）、行类别色与徽章、快编 token（`d=` 至少可编）、右键菜单/禁用、Dev Mode 时间线行列表。发现某个面需要为新 kind 写特例，先想想是不是通用层该学会——报告里说明。
