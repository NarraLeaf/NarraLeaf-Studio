# feat: 界面专业化

上一轮（`2026-07-22-001`，17 条分支）在工程层面成功、在体验层面没有发生。本计划不是它的续集，
而是对它的**纠偏**：上一轮的立场是「不改基因，补读感」，结果证明补出来的读感在物理上看不见。
本轮的立场是**「改变量必须可测量，验收必须由 orchestrator 亲眼看」**。

## 0. 本轮铁律（与上一轮的差别就在这三条）

- **R1 每张卡都有"进攻性判据"。** 不只写"不做什么"，必须写"做完之后，什么在屏幕上必须不同"，
  且用**可断言的量**表达（对比度比值、像素尺寸、缩略图存在与否、落点行号相等）。
- **R2 验收由 orchestrator 亲手做。** 执行者的报告与截图**不构成验收**。orchestrator 拉起实例、
  驱动到指定状态、亲自截图并读图，外加脚本断言。两者都绿才合并。
- **R3 禁止"纯投影 / 只读 / 复用形态"作为默认解。** 这三个词在上一轮是免罪符。本轮若某个 WI 要走
  投影路线，必须在卡里论证"为什么这次投影足够"，否则默认允许改结构。

## 1. 现场勘验（2026-07-24，orchestrator 亲测，develop @ `41273b81`）

方法：`yarn dev` + CDP 9222/自建驱动，demo3 项目，视口 1400×902 @dpr 1.25。截图与量化读数见 §9。

### 1.1 故事编辑器

| 观察 | 实测值 | 判定 |
|---|---|---|
| 对话分组导轨（"这行是谁说的"的唯一载体） | `1px` / `rgba(255,255,255,0.1)` | 对比度 ≈1.1:1，**物理上不可见**；仅 hover/active 时变 `rgba(64,168,196,0.4)` |
| 行类别色条 | `2px` / `opacity .55` | 对比度 ≈1.6:1，低于 WCAG 非文本 3:1 |
| 角色头像 | `24×24px` | 占编辑器宽度 1.7%，看不清脸；差分头像/裁剪选区的全部工作在此尺寸下不可见 |
| 编辑面背景 | `rgba(0,0,0,0)` | 完全透明，工作区背景照片一路透到正文 |
| 组内成员行 vs 旁白行 | 渲染**完全相同** | 分组之后作者无法区分"某人的后续台词"和"旁白"——分组使信息**减少** |
| `/bg` 行的背景缩略图 | 铺满行右侧 | 把行文本截断成 `Set backgr...` |
| 右栏 Properties | 选中第 8 行时仍显示 `No item selected` | 600px 面板恒空；检查器与选择完全脱节 |
| 行内 hover 动作 | 文字按钮 `Insert Delete ▷` | 与正文同字号，压在内容上 |

### 1.2 Dev Mode

| 观察 | 实测 | 判定 |
|---|---|---|
| 调试面板布局 | `absolute inset-y-0 right-0 w-380px` | **覆盖舞台右侧 380px**；打开面板的第一秒立绘就被切掉一半 |
| 时间线行文案 | `character enter · character`、`setBackground` | 编辑器同一行是 `Enter Nattou`、`Set background outside_s.jpg d 5s`——调试器信息量**严格少于**编辑器 |
| 时间线视觉 | 全等宽灰字，12 行零分层 | 无类别、无头像、无缩进 |
| **时间线跳转** | 见下表 | **功能是坏的，不是精度问题** |
| Stack tab | 正常对白推进时显示 `Nothing on the stack` | 根栈在非容器场景恒空 → 该 tab 约 99% 时间无内容 |
| Variables tab | 只列出 1 个 `Var`，Local/Persis 空 | 面板 90% 空白 |
| Scenes tab | 3 个 ~7px 字号节点浮在未 fit 的空画布上 | 不可读 |
| 唤起入口 | 左下角 FAB = 产品 favicon | 不表达任何功能 |
| 快照选择器 | 原生 `<select>` | 与全 app 设计语言不一致 |

**跳转实测（四次，全错，规律一致）**

| 点击目标行 | 起点 | 实际落点 | 偏差 |
|---|---|---|---|
| 10 `The journey is about to begin.` | 5 | **7** | −3 |
| 12 `setBackground` | 7 | **9** | −3 |
| 2 `character enter`（后向） | 9 | **3** | +1 |
| 9 `Narra: OK` | 3 | **5** | −4 |

结论：**前向跳转永远只前进 2 行，与点击目标无关**；后向跳转落 N+1。
即 M5 交付的"两层时间线冷跳/热跳"在真机上不工作。该功能通过了复核（MERGEABLE-WITH-NITS，
nits 为死 i18n key 与 dimmed-Local），**说明没有任何人点过一次时间线的行**。

## 2. 为什么"廉价"——八条根因（每条对应后面的 WI）

- **C1 透明编辑面。** 正文表面 `rgba(0,0,0,0)`，装饰背景照片与所有前景元素抢对比度并全胜。
  专业工具（VS Code / PR / Figma）的编辑面是**不透明**的。这一条单独解释大部分廉价感。
- **C2 用亚像素线承载一等语义。** 分组归属、动作类别是"必须一眼看到"的信息，被编码成 1–2px 的线。
  信息层级与视觉层级倒挂。
- **C3 空面板 + 一句解释文字。** `No item selected` / `Nothing on the stack` / `No videos yet` /
  `No json files yet` / `No Build output yet`。既违反铁律，又暴露"面板在但没内容"。
- **C4 缩略图缺席。** 视觉小说 90% 的资产是图像；资产侧栏、图标视图、资源总览、时间线全是文件名与数字。
- **C5 内部词汇泄漏。** `character enter · character`、`setBackground`、`Stage name: character`、
  `content/35/f4/5bbaf…`、`3f2a91c…`、完整 hash。
- **C6 数字砖块当信息设计。** Dashboard 12 块 + 总览 6 块，每块 ~250×90px 表达一个整数。
- **C7 布局不由内容决定。** 恒空的 600px 面板、覆盖舞台的调试抽屉、未 fit 的场景图、溢出的行内缩略图、
  换行的 `22 items`。
- **C8 每个视图各造一套语言。** 编辑器行 vs Dev Mode 时间线两套 describe；资产侧栏 vs 总览两套列表；
  分组导轨 vs 类别色条两套"左缘线索"。

### U0 阻断级修复

- **U0-1 跳转根治。** 建 `blockId → historyToken` 映射（播放/快进途中从 `getHistory()` 收集）；
  点击**已播过**的行 = `restoreToHistory(token)`，即时精确零重放；未播过的行才走 fastForward，
  且必须**先证明**当前 `until:{actionId}` 语义能落到目标——不能就开引擎卡要 `after:{actionId}`。
  删掉 `StoryRuntimeDebugPanel.tsx` 那个吞掉回落失败的 `.catch(() => {})`。
  - 判据：脚本断言 **点击第 N 行后播放头行号 == N**，对 12 行场景全覆盖，前向/后向各一轮。
- **U0-2 调试面板不再遮舞台。** 面板从 `absolute` 覆盖改为**挤压布局**（stage 与面板同为 flex 兄弟），
  舞台按剩余宽度重新 fit。
  - 判据：打开面板前后各截一张，**立绘完整可见**，舞台无裁切。
- **U0-3 编辑面不透明。** 故事编辑器正文区、检查器、Dev Mode 面板的表面改为不透明；装饰背景只保留在
  空态/外围 chrome（侧栏、标题栏、tab 条本轮不动）。
  **裁决（用户 2026-07-24）：工作区背景图功能保留**——它是可选配置，用户不想要可以关。
  因此本项不是"删背景图"，而是"让开着背景图时正文依然可读"；**验收必须在背景图开启状态下量**。
  - 判据：取正文区 `backgroundColor` 的 alpha == 1；正文文字与背景对比度 ≥ 7:1，**背景图开启时测**。

### U1 阅读层重做 —— 两档密度

**裁决（用户 2026-07-24）：做成真正的两档，替换掉现在那个 `fontSize × 1.15` 的 comfortable density。**
接受"两套渲染路径要一起维护"的代价。两档共用同一份投影与同一套行机械（选择/拖拽/编辑/播放头），
差别只在行的**布局与 chrome**——不是两个模式，是一个表面的两种排版。

- **U1-0 退役旧密度。** 删除 `storyEditorTextStyle.tsx` 里 `COMFORTABLE_FONT_SCALE` / `COMFORTABLE_LINE_HEIGHT`
  那套字号缩放。字号继续由 Settings 的 `editor.fontSize` 管，密度不再动字号。

- **紧凑档（默认，对标"专业工具的信息密度"）**
  - **U1-1 行号与把手让位。** 常驻 64px 的行号+把手列收窄；把手 hover 才出现；行号弱化但保留。
  - **U1-2 头像入行且可辨识。** 头像从 24px 提到 ≥28px 并在同说话人连续行里只出现一次；
    组内成员行必须有**可见**的归属线索（左缘条 ≥2px 且对比度 ≥3:1，或缩进 + 可见导轨）。
  - **U1-3 类别可见化。** 类别不再靠 `2px / opacity .55`：可见宽度的左缘条 + 徽章底色，对比度 ≥3:1。
  - **U1-4 行内动作图标化。** `Insert / Delete / ▷` 文字按钮改图标，不侵占内容宽度。
  - **U1-5 `/bg` 行缩略图定型。** 缩略图不得截断行文本；固定尺寸、不铺满行宽。
  - 密度判据：一屏可读对白行数 **不低于现状**。

- **宽松档（对标 LetsGal 的阅读体验）**
  - **U1-6 对话块。** 连续同说话人 = 一个**块**：左侧一列头像（≥40px）+ 角色色名字，
    右侧多行台词；块内不重复头像与名牌。允许改 grid 结构——上一轮"三列不动"的约束**作废**。
  - **U1-7 表情行入块。** 同角色 `/face` 行渲染为块内的弱化标注（差分名 + 小头像），不打断块。
  - 密度判据：一屏可读对白行数允许比紧凑档低，**但正文字号不得变化**（放大字号不是密度）。

- **共同判据（orchestrator 亲测）**：
  - 两档下都能**不看头像判断第 7、8 行属于 YouKi**（demo3 `First Day`）；
  - 导轨/色条对比度 ≥3:1（**背景图开启时测**）；
  - 切档不丢选择、不丢滚动位置、不改文档；
  - 两档的行机械完全一致（同一行在两档下右键菜单、拖拽、Enter、播放头高亮行为相同）。

### U2 检查器

- **U2-1 跟随选中。** 选中行 → 右栏立即显示该行的检查器（保留 Enter/双击的既有语义）。
- **U2-2 消灭空态文案。** 无选中时右栏不显示 `No item selected` 文案；面板要么收起、要么显示场景级属性。
- 判据：点任意行，右栏 1 帧内出现对应内容；全 app 搜索 `No item selected` 类文案归零（U5 兜底）。

### U3 资产管理器

**裁决（用户 2026-07-24）：做完整版**，因此拆成两张卡——U3a 先把"看不见图"这个硬伤治掉并可独立发布，
U3b 再上管理能力。U3b 触碰资产写路径，风险等级高于 U3a，必须单独验收。

#### U3a 浏览层

- **U3a-1 真缩略图。** Icon view 必须显示真实缩略图（图像立即；视频首帧、音频波形可占位但要成体系，
  **不许用通用文件图标冒充**）。修正表头 `Images / 0 assets` 的计数错误（分组内资产未计入）。
- **U3a-2 分组卡片有内容。** `Character` / `UI` 这类分组不再是空白卡片：显示前 N 张缩略图堆叠或网格预览。
- **U3a-3 搜索与筛选。** 按类型、是否被引用、大小、标签筛选；搜索命中要能跨分组。
- **U3a-4 总览并入。** 资源总览从独立 tab 降级为资产管理器的一个视图；6 块数字砖压到一行；
  `Largest` / `Unreferenced` 列表**带缩略图**。`AssetOverviewCommand` 的独立入口随之退役。
- **U3a-5 详情面板去内部词汇。** 分片路径 `content/35/f4/…` 与裸 hash 不再直接示人（可折叠/可复制）。
- 判据：打开 Icon view 截图，**每个图像资产可见其内容**；总览首屏能看到资产本身而不只是数字；
  搜索 "nattou" 能跨分组命中。

#### U3b 管理层

- **U3b-1 就地操作。** 重命名、删除、移动分组，走既有 `ContextMenu` 与 undo 路径。
- **U3b-2 批量选择与操作。** 框选/Shift 多选 + 批量移组、批量删除、批量打标签；
  删除必须经 `ReferenceService` 反查并在**被引用时明确拦截**（这是玩家侧缺资产的唯一防线）。
- **U3b-3 替换资产内容。** 保 id 换文件（所有引用点自动跟随），hash 与尺寸重算，缩略图失效重建。
- **U3b-4 标签管理 + 导入队列。** 标签的增删改；多文件导入时的进度与失败项可重试。
- 判据：批量删除一个被引用的资产必须被拦住并指出引用点；替换资产后所有引用点的渲染同步更新
  （故事行缩略图、角色差分、UI 元素各验一处）；导入 20 个文件全程有进度且失败可重试。

## 5. 验收协议（R2 的具体机械）

每张卡的生命周期：

1. orchestrator 写卡，**判据章节由 orchestrator 写**，含：驱动路径（点哪里到哪个状态）、
   要截的图、脚本断言的量。
2. 执行者实现 + 自验 + 交报告（报告**不是**验收）。
3. **orchestrator 亲手验收**：
   - `yarn dev` 拉起实例，用 `tools/ui-verify/` 的驱动脚本走到指定状态；
   - 亲自截图并**读图**；
   - 跑该卡的断言脚本（对比度、尺寸、落点行号、缩略图存在性）。
4. 目视 + 断言双绿 → 合并；任一不绿 → 退回，**不接受"测试全绿所以通过"**。

**新增基建（U0 一并做）**：把本次勘验用的 CDP 驱动固化为 `tools/ui-verify/`：
`drive.js`（连接/截图/点击/求值）+ `assert.js`（对比度、计算样式、播放头行号）+ 每卡一个 `scenarios/*.js`。
这样"验收"是可复现的命令，而不是一次性手工操作。
