# First-run setup (OOBE)

状态：完成，分支 `feat/oobe`。真机验收记录在 §7。

## 1. 为什么需要

安装后第一次启动，Studio 落在 launcher 的 Projects 页，列表是空的，两个按钮。没有任何东西问过作者一句话。这带来两个**在代码里可以指出来的**问题：

- `"app.language"` 的默认值是硬编码的 `"en"`（`@shared/types/state/globalState.ts` 的 `GLOBAL_STATE_DEFAULTS`），**没有任何设备语言探测**。而同一个仓库里 `editor.slashAtAlias` 是读 `navigator.languages` 判断简体中文的（`lib/settings/slashAliasOptions.ts`）。也就是说 Studio 在一处知道这台机器说中文，在另一处装作不知道，于是中文作者的第一屏是英文。
- 主题、强调色这些「基础偏好」只有在作者主动打开设置窗口时才会被发现。它们全都是**立即生效**的（主题走主进程的 `nativeTheme.themeSource`，纯 CSS；强调色由 `lib/appearance` 覆写 `--nl-primary`），所以在首次运行时问一次，代价接近零，收益是作者从第一分钟起就在自己选的界面里写作。

## 2. 范围（裁决）

**只放基础设置与偏好，不放工程级别的东西。** 三屏：

1. **语言** —— 按设备语言预选，改了立刻重排整个窗口。
2. **外观** —— 主题（跟随系统 / 浅色 / 深色）+ 强调色预设，两者都当场生效。
3. **完成** —— 说清这些在设置里，以及 F1 是干什么的。

### 明确不做，以及为什么

| 不做 | 理由 |
|---|---|
| 功能巡览 / 轮播 / 每日提示 | 帮助系统那一轮已经删掉 launcher 的卡片墙，并**明确否决**了引导式教程与启动提示（"启动弹窗是最吵的说法"）。再加回来等于把刚删的东西装回去。F1 与学习页就是"这是什么"的答案。 |
| 镜像源 / 下载地址 | 普通作者不会用到，而且 `DownloadSourcesPanel` 已有裁决：**不随产品附带任何预设镜像**，因为哪天它不响应了，读起来像产品坏了。这是工程/发布侧的设置，不是首次运行该问的。 |
| 提交署名（`versionControl.author*`） | 属于工程级别的概念，不该在作者还没有工程的时候问。**遗留缺口如实记在 §6。** |
| 在 OOBE 里建工程 | 工程向导是独立窗口、三条流程、七个步骤。吞进来就是抄一遍；结束在 launcher、向导离一次点击，是现有空状态已经做对的事。 |
| 遥测同意 | `advanced.enableTelemetry` 在 `RETIRED_GLOBAL_STATE_KEYS` 里，产品**没有**遥测。问了就是撒谎。 |
| 界面缩放 `ui.zoomPercent` | 设置里有行，默认值对绝大多数人是对的；而首次运行时作者手上没有工程，**没有可供判断缩放是否合适的东西**，那个滑块只会招来无意义的摆弄。 |
| OOBE 内的 `?` 帮助入口 | 帮助主题是给"回到一个你已经认识的界面"用的。OOBE 是那个**必须自己把话说完**的界面，所以话写在控件旁边（三层文字里的"预期"层），不外链。 |

## 2.5 顺带修掉的根因：`app.language` 的默认值

**这一条超出了「加一个 OOBE」的字面范围，是有意的**：不修它，第一屏就是一个用英文问中文作者
「你要用什么语言」的界面，屏幕本身就是那个缺陷的展示。

做法照抄仓库里已有的先例（`editor.slashAtAlias` 的注释写着为什么）：
**`app.language` 从 `GLOBAL_STATE_DEFAULTS` 里拿掉**，「没存值」由两侧各自按机器语言解析。
两侧共用 `@shared/i18n` 的 `resolvePreferredLocale(tags)`，只是 tag 从哪来不同——
渲染层 `navigator.languages`，主进程 `app.getPreferredSystemLanguages()`。
**一个「这台机器说什么语言」的实现，不是两个**，否则原生菜单和窗口会各说各话。

它是**走一遍列表取第一个 Studio 真有的语言**，不是只看头一个：有序列表是偏好顺序，
一台先要法语再要中文的机器，在没有法语的 Studio 上想要的是中文而不是兜底的英文。

连带三处：设置里语言那行的 `defaultValue` 改成解析结果（否则设置显示 English 而界面是中文）、
`menuManager` 的菜单 key 用解析后的值（否则每个 profile 都 key 同一个 `undefined`）、
诊断包里的 `locale` 同理。

## 3. 它挂在哪里

**是 launcher 窗口的一个模式，不是新的 `WindowAppType`。**

决定在主进程做，作为**窗口 prop** 交给渲染层，所以第一帧就已经是对的，不会先闪一下工程列表。这正是 `WindowProps[Workspace].recovery` 用的机制，它的注释把理由写死了：*"the flag is the first thing the new renderer reads and nothing has to be told twice"*。

不新开窗口类型换来的是：`window/permissions.ts` 不用加行、`navigationGuard` 不用加行、`WindowCloseResults` 不用加分支、构建脚本不用动（`getRendererApps` 是按目录扫的），以及**"设置到一半把窗口关了"不需要设计第三种状态**——关掉它就是关掉 launcher，和一直以来一样。

```
marker 缺失 或 --onboarding(仅 dev)
        ↓  主进程同步读 globalState
  launchLauncher({ onboarding })
        ↓  首帧
  设置流程  或  launcher 主页
```

## 4. 标记与 dev flag

- **`app.onboardingVersion: number`，故意不进 `GLOBAL_STATE_DEFAULTS`。** 缺失就是"没走过"。给它一个默认值会让所有既有 profile 看起来都已经走过。
- 它**不是偏好**，是这个安装的状态。所以它没有 registry 行；而还原 / 导出 / 导入三个范围**全部**是从 registry 算出来的（`lib/settings/settingsScope.ts`），因此一个没有行的键天然在三者之外，**不需要在任何清单里登记**。
- **版本号而不是布尔**：布尔表达不了"走过的是旧版设置"。但是**升号是一次刻意的产品动作**，语义是"下次启动给所有人重放整个流程"，加一屏本身不构成升号的理由。
- `--onboarding`，在 `commandLine.ts` 里和既有 flag 一起解析，**只在 `isMainDevMode()` 为真时被承认**（即未打包且带 `--dev`）。打包版忽略它：argv 会从快捷方式和文件关联进来，那不是让界面改道的地方。
- **标记只在流程被刻意结束时写**：走完按「打开 Studio」，或在任意一屏按「跳过设置」。**中途退出（关窗、崩溃、退出应用）什么都不写**，下次启动重放。反过来那种做法（首帧就标记完成）意味着一次崩溃永久吃掉语言那一问。
- 「跳过设置」写标记，是诚实的：它说的是"不用再问我"，而不是"我等下再来"。流程只设两样东西，两样在设置里都有行，所以跳过不损失任何能力。
- 副作用是对的：关掉工程回到 launcher（`ensureLauncher`）时不会再弹设置，因为标记已经写了。

## 5. 设计规范上的约束

- 只用共享组件（`Button` / `Select` / `FieldLabel`），一排控件同一个 `size`。
- **没有步骤指示器**。三屏里只有两屏在问东西，一条进度点串在这儿属于装饰。
- 强调色只给 `ACCENT_PRESETS` 五个预设，**不带自定义取色器**——`accent.ts` 自己写着预设是"the guided path"，首次运行就是那条路；任意颜色留在设置里。色块的视觉语言照抄 `SettingsExplorer` 的那一排（`h-5 w-5 rounded-full`，选中 `ring-2 ring-offset-2`）。
- **没有主题预览小图**。规划时想画三张缩略图，做的时候推翻了：这一屏所有东西都是选了当场生效，
  **窗口自己就是预览**。在一个已经变成浅色的窗口旁边再画一张"浅色长这样"的图，是在画现在。
  （附带好处：不用为了让预览块不跟着主题翻转而新增一组硬编码颜色，`arbitrary-hex` 那项债务没动。）

## 6. 真机验收（CDP 9377，worktree 自己的 userData，简体中文设备）

八条，全部在跑起来的 app 上看过：

1. 全新 profile 开机 → 设置流程出现，**整屏是中文**（`htmlLang=zh-CN`），没存过 `app.language`。
   这一条就是 §2.5 那个修复的证据。
2. 第一屏：语言下拉显示「中文」+「按这台设备的语言选好的」，「返回」是禁用的。
3. 第二屏：主题下拉 + 五个色块，`aria-checked` 只有一个是 true。
4. 选「亮色」→ `colorScheme` 当场变 light；选「玫瑰」→ `--nl-primary` 当场变 `196 110 156`。
   两者都不需要重启，也不需要离开这一屏。
5. 第三屏只有「返回」和「打开 Studio」，**没有跳过**——这一屏的主按钮就是出口。
6. 按「打开 Studio」→ 同一个窗口换成 launcher 主页，`app.onboardingVersion` 写入 1。
7. 重启（不带 flag）→ 直接是主页。
8. 带 `--onboarding` 重启 → 尽管标记在，设置流程照样出现；在第一屏按「跳过设置」→
   回主页且标记仍是 1。

一处**量了才知道不是缺陷**的：截图上第一个色块的选中环看着像被容器切掉了。
量出来 `swatchLeft === headingLeft === 176`，环是 4px box-shadow，滚动容器左边在 0、内边距 40 ——
没有裁切。**先量再改**，不然就会为一个不存在的问题动样式。

## 7. 已知未解决

以下两条是规划时查出来的真实缺口，本轮**按裁决不在 OOBE 里解决**，记在这里以免被当成已经处理过：

- `versionControl.authorName` / `authorEmail` 对每个安装都是 `""`，而 `checkpointIntervalMinutes` 默认 15、`checkpointOnClose` 默认开。也就是说每个作者从第一分钟起都在产生没有署名的版本，产品里**没有任何一处**会问。
- 下载地址不可达时失败得很晚且难以归因：商店能浏览、点安装超时；构建走到一半取不到 Electron。`app.probeDownloadSource` 这条 IPC 已经存在，启动路径上没人调用它。
