## WI-1 主语归属对齐（主菜）

`/` 空态浏览改调 `buildSpecSidebarGroups`——与侧栏同源。`/show` 现按 `accepts` 出现在角色/图片/文字/图层/视频/氛围特效六节下（次序＝侧栏 group 次序，稳定可预测）。**高亮不变式与多主语归属两者皆成立，无需牺牲**：新增 `browseMenuStops`（specSidebar.ts）把浏览网格摊成"每渲染行一个 stop"，walk 键＝`group:id` 复合键。同一 `/show` 是六个 distinct stop，一次按键走一行，`active` 恒只一行，Enter 取眼睛所见那行（规则 2）。行图标随**所在节**（与侧栏同规则）。**输入态不动**：一打字即回落扁平排序候选（`options`），每命令一条。
测试（specSidebar.test.ts +4）：`/show` 六节各一次、每 stop 键唯一（高亮不重复命中）、六个 show 是六个 stop、walk 序＝侧栏序。
**指令手册保持单点归属，不对齐**：手册是查阅面（签名/别名/说明），签名本身已列出可接受目标，一命令一条才是索引的正确形态；把 `/show` 在手册里重复六次是噪声，不是 D1 的"两套心智模型"不一致。已在此说明。

## WI-2 `/fx` backdrop + blend

按引擎 0.16.1 d.ts：`backdrop(css, opts)` 收原始 `backdrop-filter` 串——与既有 `filter` op 同惯例（检查器同款 TextField，空串走 warning）；`blend(mode, opts)` 形参是 `React.CSSProperties["mixBlendMode"]`（CSS 全集），但**只暴露引擎自有的 6 个枚举** `StoryVfxBlendMode`（复用 `vfxBlendOptions` 下拉，与氛围特效同一套），不照抄 CSS 全集。payload 加 `backdropFilter?`/`mixBlendMode?`（additive，无 schema bump）；编译 `compileDisplayableEffect` 加两 case + `DISPLAYABLE_EFFECT_OPS` 补两项；i18n en+zh。**钳制**：两 op 均经 `effectVisualOptions` 的共享时长下限 `Math.max(0, durationMs)`——`backdrop` 无 0..1 数值，`blend` 是枚举，故可钳的数值就是共享时长。测试 storyCompiler.effects.test.ts（新文件，3 条）：backdropFilter 透传 + 负时长钳到 0、blend 模式透传、空 backdrop 出 warning。

## WI-3 结论（只给结论，未改语义）

1. **插件色调：可接受，不加带色 group。** 带色 group＝按"来源"再切一刀，正是 13→8 消除的东西；插件即工具，归「工具」。若日后要可辨识性，保 taxonomy 的杠杆是 Puzzle 图标（palette 数据里已有），不是色相——但当前"行图标随节"规则把它也盖成灰 StickyNote，插件遂与 `/note` 同款。WI-1 令 `/` 浏览与侧栏一致（都随节图标），故插件两面同为灰 StickyNote（一致性＝WI-1 目标）；恢复可辨识性（单主语条目保留自有图标，两面同改）是后续，非本卡。
2. **`/stop petals` 静默：值得加诊断，但不是"解析不到任何对象就诊断"。** `resolveTarget` 对**拼错**与**合法动态/跨场景对象**都回 `known:false`，一刀切会误伤后者。精确可检测的是：具名目标命中了一个**已知但动词不接受其 kind** 的对象（petals 是已知 vfx，`/stop` 只 accepts audio/video → 静默转 audio）；`collectStageObjects` 已收 vfx 名，可判。建议对这一类出诊断（"petals 是氛围特效，/stop 不能作用于它，试 /pause"），保留 fallbackKind 给省略目标(BGM)与真动态名。纯拼错与合法动态名不可分，宜维持运行时 no-op（停一个没在播的音效本就无操作，与 NLR 语义一致）。
