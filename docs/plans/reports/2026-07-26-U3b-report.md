## 2. 每个 WI 的做法与取舍

### WI-1 替换资产内容

顺序按卡里写的走，且**编排放在 `AssetsService` 而不是 manager 里**，这样任何调用方都不可能只做其中三步：

1. `LocalAssetsManager.writeAssetContentFromPath` — 校验格式（与导入同一道 magic-bytes 关口）、
   `copyFile` 覆盖同一个 `AssetsDataShard(id)`、**对目标文件**重算 hash。它**不写元数据、不发事件**。
2. `AssetsService.clearThumbnailCache(assetId)`。
3. `AssetsMetadataManager.applyReplacedContent` 写 hash/ext/name + `markDirty`。
4. `emit("updated")` —— 最后一步。

**取舍：**

- `hash` 算不出来时落 `""`（与导入现有的兜底一致）而不是保留旧值。理由：旧值不变会让所有拿 hash
  当 React dep 的地方永远读旧图，这正是本条要修的病；`""` 至少与旧值不同，能触发重读。
- 换了扩展名（png→jpg）会同时改 `ext` 和显示名的后缀，并在同类型内做去重（排除自己）。
  不改名会让 `ext` 与名字互相打架，而 `ext` 是编译进包时的文件名依据。
- **入口两个**：单资产右键 `Replace File…`（分组不出现）+ 检查器按钮。没有批量替换。
- 确认框**没有解释句**：`Replace the contents of {name}?` + Cancel（主按钮、键盘默认）+ Replace
  （危险色次要）。这是"不可撤销"唯一的表达方式，按 §6 的要求用层级说。
- 引用点跟随：`storyBadgeImageCache` 本来就订阅 `updated`；**`useAssetObjectUrl` 原来只 key 在
  `assetId` 上**（id 按定义不会变），所以故事行、角色差分选择器、UI 控件填充在替换后都不会重画 —— 这
  条是这次一起修的，加了一个 `updated` 订阅驱动的 generation。

### WI-2 引用守卫下沉

- 反查从 hook 移到 `AssetsService`：`deleteAsset` 逐个查，`deleteGroup` **在枚举阶段**对级联会波及
  的全部资产（含任意深度子分组）一次性查。枚举阶段是必须的——放在级联循环里逐个查的话，等到第三个
  文件被拒时前两个已经删掉了。
- 语义 = 默认阻止 + `{ allowReferenced: true }` 显式放行。UI 在作者看过引用清单并确认后才传它。
  服务层不弹 UI，只拒绝。
- **UI 与守卫读同一份反查**（`assetsService.findAssetReferences`），不再各查各的——两份查询早晚会
  不一致，而作者看到的那份不是说了算的那份。
- `GroupAssetsManager.deleteGroup` 现在**遇到单项失败就中止**并把错误往上抛。原来是无视失败继续，
  最后照样把分组记录删掉：那会让被拒绝的文件孤零零留在根目录，作者再也找不回它原来在哪。
- 三个删除弹框（引用警告 / 无法核实 / 最终确认）统一换成 `showDestructiveConfirm`。

**关于 §10 的"签名要改就先停下来说"**：不需要停。`ReferenceService.ensureReady` 是异步的，但
`AssetsService.deleteAsset` **今天已经是 `async`**（返回 `Promise<RequestStatus<void>>`），所以只是
加了一个可选参数，没有同步→异步的语义变更，也没有引入死锁：`ReferenceService` 通过服务注册表在
**调用时**解析（`import type` 只在类型层），没有 init 期依赖，因此不会和"引用索引要扫的文档反过来读
资产"形成环。

### WI-3 导入队列

- `importFromPaths` 加可选 `onProgress`，每个文件前报一次、结束再报一次。1:1 的 path→result 契约
  没动（VoicePanel 按下标取结果）。
- **两个入口都先解析出路径再导入**：拖拽分支原本就有，选择器分支原来是在 importer 内部弹的框，现在
  提到 UI 层。这是"总数已知"和"失败可重试"能成立的前提。
- 进度与失败列在**面板内的一行**（`ImportQueueStrip`），不是浮层——二十个文件的拖拽本来就发生在面板
  里，浮层会盖住作者正在拖的那棵树。进度条复用既有 `Progress`。
- 吞提示的缺陷：`groupId` 分支的移动失败原来 `return`，同时放弃了剩余移动**和**还没弹出来的导入失败
  汇总。改成收集后一并报，两条路都不再静默。
