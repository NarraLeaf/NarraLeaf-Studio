## 2. WI-2：两处内部词汇

### `Stage name` → `Refer to as`（zh：`后续称呼为`）

key 也一并从 `character.stageName` 改名为 `character.objectName`，免得 UI 不说 stage 而代码还说。

措辞理由：这个字段的用途是**后续指令怎么指到这个角色**（`/move Nattou`、`/hide Nattou`），
所以按「作者拿它干什么」命名，而不是按「引擎把它登记成什么」。不含 "Stage"、不含 "name"。

**默认值不再看起来像输入的内容**：两种东西会在没人打字的情况下把值填进去——
bare block 的字面量 `"character"`，和选角色时从档案带过来的自动填充。两者都不是作者写的，
所以都以 **placeholder** 呈现（灰色的角色名），只有作者真正挑过的名字才作为值显示。

判断「是不是作者写的」直接问 `characterStageName`（`shared/types/story/displayableTarget.ts`）——
那条规则本来就把 `"character"` 当未设置、改用角色 id 作键——而不是在组件里另立一套：
**stage key 与去空白后的文本不相等，就说明那段文本从来不是一个名字**。

**纯显示改动**：payload 里已有的值原样不动，打字仍然原样写入。没有 schema、没有编译器改动。

### `Text ID` → 折叠 + 可复制

标签改成 `Localization key`（zh：`本地化键名`）——它是翻译与配音给这一行编的号，
按「它是干什么的」命名而不是「它是什么」。

裸 uuid 收进一个折叠块（`aria-expanded`），展开后一行等宽字 + 一个复制按钮，
照 U3a 给资产 hash / 分片路径定的形状（`AssetOverviewView` 的 `CopyRow`）做。
默认折叠 ⇒ 检查器默认不打印 uuid。

`aria-labelledby` 且子节点无字面文本 ⇒ 候选。首轮 7 个候选，其中 5 个是真的：

| 文件 | 按钮 | 处理 |
|---|---|---|
| `assets/AssetsPanel.tsx` ×2 | Refresh（宽/窄两套工具栏） | `title` + `aria-label` = `common.refresh` |
| `project-wizard/steps/SettingsStep.tsx` | 位置输入框里的文件夹按钮 | 新增 key `wizard.settings.browseLocation`（en/zh 同加） |
| `properties/editors/BasePropertyEditor.tsx` ×2 | 加标签 / 删标签 | 复用 `properties.tags.add` / `tags.remove` / `tags.removeAria`（`TagsField` 里的同胞早就有名字，这份副本一直没有） |

另两个候选是 `Button` 与 `Switch` 两个基础组件，名字由调用方给（`Switch` 还被 `<label>` 包着，
`button` 是可被 label 标注的元素）——不是缺陷。
