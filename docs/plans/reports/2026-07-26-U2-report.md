## 2. 每个 WI 的做法与取舍

### WI-1 选中驱动右栏

`SelectionState.type` 加 `"storyBlock"`，data 是 `{ editor:"story", tabId, storyId, sceneId, blockId }`。

**一个成员而不是两个**：`blockId: null` 表示"没有选中行，主语是场景本身"。多加一个
`storyScene` 成员会让分派点翻倍，而右栏在场景标签页在前台时**永远**有主语，本来就没有第三种状态。

**选中只带地址，不带内容。** 块、文档、角色表、编辑回调仍走 `storyInspectorBridge`
（`useSyncExternalStore`）。两个理由：

1. 选中里塞一个 `StoryBlock` 会让面板渲染"选中那一刻的快照"——改说话人、在行上直接改 payload 都不会刷新；
2. 行→行切换靠桥的**同步**更新落在点击的同一个 commit 里，不必等 `selectionChanged` 那个
   `startTransition`（面板里既有的写法，我没动）。

发布点是 `StorySceneEditorTab` 里一个 effect，依赖 `editor.activeBlockId` 等。**只在 store 里
不是我们的选中时才写**，所以一次无关按键引起的 republish 不会多发一个 selection 事件。

**`selectionRevision`（新增，controller）**：`selectRow` 每次调用都自增。没有它的话，"点资产→
再点回**同一行**"不改变任何 state，effect 不重跑，右栏会一直停在资产上。这是我加的第二个状态，
代价是每次点击多一个 setState——和它同批的 `setActiveBlockId`/`setSelectedBlockIds` 一起被 React 合并，
没有额外渲染。

**手工过的分派点**（卡片提醒"加成员不会产生编译错误"）：`PropertiesPanel.tsx` 的选中订阅、
标题/副标题、`renderPropertyEditor`。其它 `SelectionState` 读取点（`usePropertyEditor`、
`openDraggedAssetsInEditor`、`useAssetFocus`、`useCharacterFocus`）都是"写自己的类型"，不需要改。

**`SelectionType` 我选择补齐，而且是结构性补齐**：`export type SelectionType = SelectionState["type"]`，
并删掉 `usePropertyEditor.tsx:195` 的 cast。理由：手抄一份联合类型第二次一定会再漂。
用的是 `import type`，运行时模块图不变。

### WI-2 退役独立 Inspector 面板

删掉 `STORY_INSPECTOR_PANEL_ID` 的注册/`updatePayload`/`panels.show`/`panels.hide`、
`shownInspectorBlockRef`、`StoryInspectorPanel.tsx` 与 `story.sceneEditor.inspectorPanel`。
现在故事标签页**一次 `panels.show/hide` 都不调**（其它三个面板只在注销时 hide，行为未变）。

Enter / 双击语义保留：`activateBlockForInspectorOrOp` 仍然 `setEditorMode({kind:"inspector"})`，
`enterEditOrInspectorForActive`、右键菜单的 "Open inspector"、`insertBlock(..., openInspector)` 全部原样。
它们只是不再让面板出现——面板本来就在。

**取舍：`editorMode.kind === "inspector"` 现在没有任何可见效果。** 它不再被任何渲染读取
（我 grep 过：行列表里唯一一处曾经读它的 `BackgroundRowArtwork` 门槛在更早的提交里已经去掉了）。
我**保留**了这个 mode 而不是删掉，因为删它要动 Enter/双击/右键/插入四条路径，超出"接线"的范围。
后果是：在一个动作行上按 Enter 现在没有任何可见反馈（右栏本来就已经显示这一行）。这是本卡带来的
真实体验变化，写在这里而不是藏着。

**取舍：删掉了 `ActionInspector` 头部的关闭按钮（X）。** 它调 `closeInspector`，而
`closeInspector` 现在对右栏没有影响——行还选着，面板还显示这一行。一个点了没反应的按钮比没有按钮更糟。
Escape 的键盘路径保留（`ActionInspector` 根节点的 `onKeyDown` 仍然 `stopPropagation` + `onClose`，
tab 级的 `escape` keybinding 也没动），行照旧保持选中。

### WI-3 场景级属性

`storyScenePropertySchema(t)`，字段严格限定在 `StorySceneUpdate` 能写的三个：场景名（text）、
描述（textarea）、默认背景（custom）。没有扩 schema，没有发明字段。

**context 的形状和卡片建议的不同**：卡片写 `{ storyId, sceneId, scene, storyService }`，我用的是
`{ scene, onUpdateScene }`。因为卡片同时要求"写路径必须复用 `editor.updateSceneMetadata`"，而那个函数
在 controller 里（它才持有 `recordHistory`）——拿着 `storyService` 直接写就会绕开撤销栈。
`onUpdateScene` 由桥透传 `editorRef.current.updateSceneMetadata`，和场景头卡片
`StorySceneOverviewBlock` 走的是**同一个函数**。

默认背景用 custom field 而不是框架的 `thumbnail` field：`thumbnail` 会裁剪并**写一个新资产**，
而这里要引用一个已存在的资产 id。控件形状照抄场景头卡片（AssetSelector + 清除按钮），
并且**显示资产名**而不是 id。

`schema.title` 我填了既有 key `properties.panel.scene`——`PropertyEditor` 根本不渲染 title
（我读了源码确认），所以不值得为它新开一个 i18n key。

### WI-4 消灭空态文案

`properties.panel.noSelection` / `noSelectionHint` 从 en/zh 删除，渲染点删除。
全 app 没有其它引用（grep 过）。

空态提前 return 成 `<div className="h-full min-h-0 bg-surface" />`——**连面板内部那个标题行也不渲染**。
改前那行会再写一次 "Properties"（导轨已经写了一次），B2 数的 12 个词里有 2 个是它。

### WI-5 表面不透明

`.nl-editor-surface` 挂在**面板根节点和内容滚动容器两处**（只在渲染故事内容时）。
两处是刻意的：根节点让标题行和正文是同一块面板，滚动容器让"量正文表面"的脚本无论抓哪一层都读到同一个值。
颜色不写死，走 `rgb(var(--nl-surface-sunken) / var(--nl-editor-surface-opacity))` 这条既有规则。

**范围限定在故事内容**：资产/角色/UI 元素的检查器保持原样。卡片写的是"右栏承载故事内容的表面"，
把整个面板一律改不透明会改到 UI 编辑器检查器的观感，超出本卡。B9 抱怨的"两个面板表面不一致"
因此只解决了故事这一半——UI 编辑器那半仍然是透明的。

### WI-6 面板标题不得出现裸 id

`describeBlockSubject(block, characters, resolveAssetName, scene, scenes)`：resolver 作为参数传入，
helper 保持纯函数，调用方（在 React 里、拿得到 `AssetsService`）提供查表。只处理
`setBackground` 和 `audio` 两个可能存下裸 id 的 payload；`describeBlock` 其余分支本来就解析成名字并有兜底。
新增一个 key `story.describe.missingAsset`（en/zh 各一条）给"id 存在但资产没了"的情况——
复用 `story.background.missingImage`（"Missing image"）去描述一段音频是错的。

### 隔离树的 `git status`

`git archive` 解出来的目录没有 `.git`，直接 `git status` 只会报 `not a git repository`——
那不能证明任何事。所以用真仓库的 `.git` + 一个**一次性 index**（`GIT_INDEX_FILE` 指向 scratchpad，
绝不碰真 index）把隔离树当 work-tree 比对：

```
$ GIT_INDEX_FILE=<scratch>/iso.index git --git-dir=<repo>/.git --work-tree=<ISO> read-tree HEAD
$ GIT_INDEX_FILE=<scratch>/iso.index git --git-dir=<repo>/.git --work-tree=<ISO> status --porcelain
ISO_STATUS_EXIT=0
lines: 0
```

**0 行**——隔离树和 HEAD 逐文件相同，里面没有任何外来未提交改动。之后在真仓库跑
`git status --porcelain`，索引未被扰动，只剩上面那 6 个外来文件。

3. **判据 H 只在标题/主语行成立，右栏正文里仍然有裸 uuid。**
