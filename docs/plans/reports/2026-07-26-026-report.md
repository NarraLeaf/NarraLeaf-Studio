## 2. 实现

### 2.1 一个元素，两种模式

同一个 `motion.div`（`role="complementary"`，`key={activePanel}` 不变）在两种模式下换 class + style：

- **固定**：`relative z-30 h-full shrink-0` —— **和改前逐字相同**，仍是舞台的 flex 兄弟。
- **浮动**：`absolute z-30 rounded-lg border border-edge-strong shadow-2xl`，脱离文档流。

**没有**做成"两个元素靠 AnimatePresence 交叉淡入"：那样切换的 220ms 里 DOM 中会同时有
两个 `role="complementary"`，任何按它取面板的东西（包括读屏）都只会拿到第一个。

舞台的宽度是**被动**回来的：面板 `absolute` 之后行容器里只剩 `flex-1` 的舞台框，
`StageViewportFrame` 的 ResizeObserver 自己发现变宽了自己重 fit。
**没有任何地方手算宽度传给 fit**（§4.2 第二条）。

### 2.2 切换控件与可访问名

新文件 `DevModePanelChrome.tsx` 导出一个 `DevModePanelModeToggle`，两个面板共用：

| 当前模式 | `aria-label`（en） | 图标 |
|---|---|---|
| 固定 | `Float panel` | `PictureInPicture2` |
| 浮动 | `Dock panel` | `PanelRight` |

- 走 i18n：`devMode.panel.float` / `devMode.panel.dock`，en / zh 两份都加了
  （zh：`浮动面板` / `停靠面板`）。en 文案逐字就是上表两串。
- 复用仓里已有的 `ToolbarButton`（`size="xs"`，它的 props 里 `aria-label` 是必填的），
  没有新造按钮样式。
- **故意不给 `aria-pressed`**：名字已经随模式变，再叠一个按下态是自相矛盾的宣告。
  （这不影响脚本——`READ_TOGGLE` 只读 `aria-label`。）

控件放在**面板自己的标题栏**（`Story Runtime` 那一行），Blueprint DevTools 面板的标题栏
也一并改成同样的一行 flex 并挂上同一个控件——模式是抽屉的属性，不是某一个面板的。

### 2.3 拖动

- **真实指针输入**：标题栏 `onPointerDown` → `window` 上的 `pointermove` / `pointerup` /
  `pointercancel`。**没有用 HTML5 `draggable`**（§4.2 第一条）。
- window 上的监听器挂在**捕获阶段**：面板正压在运行中的游戏舞台上，
  底下任何一层 `stopPropagation` 都不该能把拖动吞掉。
- 落在标题栏上的**控件**（快照 `Select`、模式按钮）上的按压不算拖动把手——
  `event.target.closest('button, [role="button"], select, input, [role="combobox"] …')` 直接放行。
- 拖动过程中的位置是 overlay **自己的 state**，只在松手时交给 `DevModeContent`。
  逐帧走 owner 的 state 会让 GameApp（整个运行中的游戏）跟着一秒重渲染六十次。
  两个 setState 在同一个 handler 里 React 会合批，交接不闪。
- 只按不动 = 标题栏上的一次点击，不改位置。
- 组件卸载时会拆掉在飞的监听器（`endDragRef`）。

### 2.4 夹住

- **每一帧都夹**，不是松手才夹：`clamp` 在 `pointermove` 里。
  往窗外猛拖的过程中也不会出现"半个面板在窗外"。
- 边界从 DOM 现量：`panel.offsetParent` 的 rect 就是浏览器给它定位用的那个盒子，
  不论面板此刻是靠 `right` 还是靠 `left` 定的位。留 16px 边距。
- 另外挂了一个 ResizeObserver：运行区自己变了（窗口缩放、会话错误横幅出现）时把面板拉回来。
  只会往回夹，不会挪一个还装得下的面板。

### 2.5 尺寸与默认位置

- 宽 380（和固定模式同一个常数）。
- 高 `min(560px, calc(100% - 32px))`。**故意不是 `h-full`**：满高的浮动面板
  在垂直方向根本拖不动，那就是卡里点名要避免的"浮动了却挪不开"。
- 默认停在**右上角**（`top:16 / right:16`），也就是它固定时所在的那一侧。
  380px 的面板贴右边缘时不可能压在舞台中心上。
- 首次拖动后改成显式 `left/top`。`left` 和 `right` **两个键始终都写**
  （不用的那个写 `auto`），换锚点是改值而不是让 React 记得删属性。

### 2.6 模式记在哪

`panelFloating` 和 `floatPosition` 都放在 `DevModeContent`，和 `activePanel` 并排，
理由也一样：时间线跳转会换掉整个 GameApp session，挂在它下面的状态每跳一次就被重置。
**跨 Dev Mode 窗口不持久化**（§4.3 明确不在范围内）。

### 2.7 顺手改到、需要过目的两处

1. **快照 `Select` 的宽度约束** 从 `max-w-[55%]` 改成 `max-w-[13rem]`。
   原来的 `55%` 是相对标题栏算的；现在 Select 和模式按钮被包进一个内层 flex，
   百分比会去解析一个由内容撑开的容器，是个自指的值。换成固定上限。
   380px 的标题栏里留给它的净空约 238px，13rem = 208px。
2. **两个面板根节点的 `border-l`** 改成只在**固定**模式下加。
   浮动时外框自己有边，里面再来一道就像渲染故障。

## 4. 我做的几何推算（不是实测，请以验收为准）

按 §2 给的 1400×902 / 运行区 `(0,40) 1400×862` 推：

| 项 | 推算值 |
|---|---|
| 浮动时 fit 面积 | `1400 × 862`（面板脱流，舞台框独占行宽） |
| 浮动时舞台盒 | 仍是宽受限：`1400 × 787.5`，居中于 y=77.25，**中心 (700, 471)** |
| 浮动面板默认位置 | 容器坐标 `left 1004 / top 16`，`380 × 560`；视口 `x∈[1004,1384]` |
| 面板是否压到舞台中心 | 1004 > 700，不压 |
| 拖 `(-220, +130)` | 目标 `left 784 / top 146`；夹取范围 `x∈[16,1004] y∈[16,286]`——**不触边**，位移应为足额 |
| 猛拖 `(-1600,-1200)` | 夹到 `left 16 / top 16`，视口 `(16,56)-(396,616)`，整个在窗口内 |
| 抓拖点 | `HEADER_GRAB` 的 5% 采样落在标题栏左边 19px 处，即标题 `<span>` 上，不是控件 |

**这些是推算，不是读数。** 窗口尺寸变了就要重算；尤其"面板不压舞台中心"这条，
窗口窄到 ~800px 以下时余量会被吃光（800 时面板左沿 404 vs 中心 400）。

## 6. 我不确定的地方（请优先看这几处）

1. **`min(560px, …)` 这个高度是拍的。** 依据是"必须留出足够的垂直拖动余量"，
   在 862 高的运行区里留下 270px 余量。但 560px 高的面板读时间线够不够、
   看起来是不是太矮，我没有亲眼看过。

2. **framer-motion 的 `animate={{width}}` 和内联 `position/left/top/height` 混用。**
   类型和构建都过了，逻辑上 motion 只写 `width` 一个值、其余走 React 的 style diff，
   但**我没有在浏览器里验证过** motion 不会在某次 re-render 里覆写这几个属性。
   如果验收看到面板位置"跳回去"，第一嫌疑是这里。

3. **模式切换时 `AnimatePresence` 的行为。** 我保持了 `key={activePanel}` 不变，
   所以切模式**不该**触发任何补间（宽度值没变）。同样没有实机确认。

4. **`ring` vs `border` 那个改动的前提。** 我是根据仓里已知的
   "narraleaf-react 注入 Tailwind v4 表，会打死 v3 靠 CSS 变量的工具类"这条经验
   预防性地避开 `ring` 的。我**没有**实测 `ring` 在 dev-mode 窗口里会不会失效——
   同理 `shadow-2xl` 也可能失效（它也靠 `--tw-shadow`）。边框是 plain property，
   一定在；阴影没了最多是少一层立体感，不影响任何判据。

5. **Blueprint DevTools 面板的标题栏**我改成了 flex 一行 + 模式按钮。
   `u4` / `u5` 的断言我通读过，没有一条摸这个面板的标题栏，
   但它不在 -026 的判据里，也就没人会去看它——**如果它长歪了，只能靠眼睛发现**。

6. **窗口很窄时的默认浮动位置。** ~800px 宽以下，右上角锚点和舞台中心的余量会耗尽
   （见 §4）。这时 D-7 那类"不遮舞台中心"的性质会失守。没有为此加任何自适应，
   因为加了就得决定"那往哪放"，而那是设计裁决不是执行者该拍的。
