## WI-2 slide → native Push

`createTransition` 的 `slide` 分支改 `new Push({ duration, direction, easing })`（options 形态，照 `PushOptions`；`direction` 仍读 stored `props.direction`，默认 `left`）。`customImageTransitions.ts` 只导出 `Slide` + 其内部用的 `WipeDirection`，删掉 `Slide` 后即空壳 → **整个文件连同其测试一并 `git rm`**，`transitions/` 目录随之消失；全仓再无引用（唯一消费者是 storyCompiler）。**stored 形状零变**：`kind: "slide"` 与 `props.direction` 键/默认原样，既有项目零迁移（有专测锁定，见 WI-4）。

## WI-3 darkness

`darkness` 分支改 `new Darkness({ duration, easing, from, to })`，那条"无公开等价物"的 warning 诊断删除。参数照 `DarknessOptions`（`from`/`to` 均 0–1 必填，无引擎默认）——Studio 默认取 `from=1, to=0`，即"新画面从黑场中浮现"，与整屏转场语义一致（`Darkness` 的行为是直接换到新图并把亮度从 `1-from` 动到 `1-to`）。检查器：`transitionOptions` 补 `darkness` 项（此前根本没进下拉）、`transitionHints` 补一条、`kind === "darkness"` 时给两个 `NumberField`（起始/结束暗度），留空即取编译期默认——与 feather/slats 等既有数值参数的惯例一致。i18n en+zh 各补 4 键（`transition.darkness` / `darknessFrom` / `darknessTo` / `transitionHint.darkness`），键集一致。

bible §1.3：表格 `darkness` 行的 ⚠️ 去掉，脚注改写为正式条款（引擎构造 + 参数 + 默认 `1 → 0`）；正文引擎基座段同步 `0.16.0 → 0.16.1`，删掉"`slide` 例外仍用 Studio 自带 `Slide`"整句，`Push`/`Darkness` 并入"各自成引擎"一列。
