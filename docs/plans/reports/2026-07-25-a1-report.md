`targetParam(accepts)` 存在，值域是 `StoryCommandTargetKind = "character" | "image" | "text" | "layer" | "video" | "audio"`——**正是主语集合**，不是别的语义。带泛型目标的 11 条指令（`/show` `/hide` `/swap` `/play` `/font` `/fx` `/transform` 与声音控制族）全部已声明 `accepts`，一条不缺。

## 落点

- **新增 `storyCommandCategories.ts`**：8 分类 + 11 group（group 带 `category`）+ `subjectGroupId`（`audio→sound`，其余同名）。`spec.category` 类型收窄为 group id，语义收窄为"无目标指令的归属"。
- **新增 `commands/specSidebar.ts`**（本卡唯一新机械）：`specGroupIds(spec)` = 有 target → `accepts` 逐个映射；无 target → `[category]`。`buildSpecSidebarGroups` 输出「分组 → 指令」，同一 spec 可出现在多组，故行 key 用 `group:id`。
- **侧栏重写**：chip = 收藏 + 全部 + 8 分类；列表按 group 分节（复用 `/` 浏览的既有节头样式，无新组件）。行图标取**所在节**的图标——否则 `/show` 挂在「图片」节下会顶着一个人像图标。
- **建块**：`createActionFromSidebar` 改走 `spec.build({}, ctx)` + `scaffoldContainer`；是否开检查器由**块**推导（`!isTextEditableBlock && hasInspector`），不再靠 id 名单，`isInspectorFirstCommand` 随之删除。副作用：侧栏建 `/if` `/menu` 现在会自动脚手架分支/选项（原来不会）。
- **`/` 菜单保持一 spec 一条**：它的高亮遍历按 command id 走，重复条目会撞键。多主语呈现只在侧栏。

## 偏离与需要点名的事

1. **收藏夹丢弃两项，不止 `conditionIf`**：`narration` 也丢——旁白**没有 spec**（bible §2 早已把 `narration` token 移除，裸文本即旁白）。同因，**侧栏不再有「旁白」条目**，这是"侧栏＝spec 的另一种呈现"的必然结果，不是遗漏。除这两项外，57 条旧 id 全部落到活 spec 上（测试逐条断言）。集合会**变小**是合并所致（`imageShow`/`textShow`/`videoShow`/`displayableShow`/`characterEnter` → 一个 `/show`），不是丢失。
2. **`/save` 与 `/global` 的 spec id 不改**（仍是 `declareVar` / `declarePersis`）：id 是 i18n 键与拼音表的键，改 id 等于无谓地搅动两张表；卡只要求改 token。
3. **bible 顺手补两行**（超出卡面，已标注）：§2「效果与其他」原缺 `/transform` 与 `/camera` 两条；既然这一节因改名被动，把两条既有指令补进立法文本比留着不完整更准。同时把 `displayabletransform` 从"被移除 token"移回 `/transform` 的别名——代码里它一直是别名。
4. **`plugin` 分类取消**，插件动作并入「工具」（§4.1）。侧栏因此少一个"按来源"的筛选面——那正是 13 分类混标准的残留。插件条目仍带 Puzzle 图标，且**不过 `localizeSpecCommand`**（它的 label 来自自己的注册，走 spec 键会回显键名）。
